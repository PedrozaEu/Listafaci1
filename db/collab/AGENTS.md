- Collaboration schema SQL lives in `db/collab/` with a local test suite (`db/collab/test/`, run against a throwaway Postgres with a platform mock) and is applied only through the migration tool with byte-identical SQL. Writes that need consistency (mark, reorder, complete, invites, roles) go through SECURITY DEFINER RPCs with `search_path=''`, expected version and a unique operation id; triggers derive authorship from the session. Why: shared data must never trust client ids or roles and must be validated before reaching the single live backend.
